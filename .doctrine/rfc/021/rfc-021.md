# RFC-021: The attribute layer: state of play, priorities and breadcrumbs for satan-attrd

> **Working document.** Mutable by design. It asserts no canon; where it disagrees
> with `docs/attributes/design-contract.md`, the contract wins and this document is
> wrong. Nothing here is a decision — it is the collected state of play, the friction,
> and the order I would spend effort in.
>
> **Evidence basis (2026-11-06).** Code read in `/workspace/satan` (`main`,
> `560068e`) and `/workspace/satan-attrd` (`main`, `9f74ae7`). No Postgres and no
> systemd reachable from this session, so every runtime claim is inferred from code,
> migrations and Nix, or quoted from a recorded observation (`ISS-011`). Claims that
> need a live host are marked **[verify]**.

## Context

The attribute layer is SATAN's metabolism: eight global control variables —
Curiosity, Hunger, Suspicion, Doubt, Cruelty (`friction`), Shame, Brooding,
Metamorphosis — that are supposed to bias behaviour and never expand permissions
(`docs/attributes.brief.md` §0). It is also the part of the ecosystem that has been
touched least in the last months, is hardest to approach, and — by its own design
intent — is not yet doing the thing it was built for.

This RFC exists because that state is spread across two repos: the daemon
(`satan-attrd`, Rust, 4,521 lines, 14 modules, 6 migrations) and the broker wiring
(`satan/satan-attribute*.el`, 749 lines) plus a 2,883-line documentation corpus whose
*authoritative* half lives in the broker repo while the code lives in the other one.
Understanding it requires reading both, and the entry documents in the daemon repo
are six months stale. That is the approachability problem, stated plainly.

What has changed since the last whole-system look (RFC-016, 2026-07-06):

- Cognition is no longer dormant: ticks run on the gateway `deepseek-flash` profile
  (ISS-012 resolved), so the metabolism now has a live consumer of its capsule.
- `ignored` exists as an observer verdict, so the outcome axis is no longer
  positive-only.
- Decay is not "deferred" any more: T-attr-2c..2f landed 2026-05-29 with 107 tests
  (hourly check, daily fire, `maintenance:<utc-day>` synthetic run-ids, seq resume).
- The goad-ask surface (SL-016) and the `reading` sensor reason (IMP-055) both
  extended the daemon — the layer is *maintained*, just never *consumed* differently.

The design corpus (`docs/attributes/`, 2,883 lines including the brief) is thorough and

### 2. What actually moves

Per `wiring-status.md` (updated 2026-10-26 — the freshest doc on this side):

- **Active:** Curiosity (sensor `segment_backlog`, hippocampus `trace_marked`),
  Hunger (outcome `worked`, sensors `typing_active`/`reading`/`typing_idle`),
  Doubt (every non-neutral outcome), Shame (widest coverage), Brooding (outcomes +
  hippocampus writes), Metamorphosis (contradicted/harmful).
- **Near-dormant:** Suspicion — needs the reserved `resonance` source; today it has
  one small positive (`searched`) against one global negative (`contradicted`).
- **Structurally locked at 0:** Cruelty/`friction` — no implemented source produces a
  positive delta, *and* the cap `friction ≤ max(0, 1 − doubt − shame)` clamps to 0
  whenever doubt + shame ≥ 1.0. With decay live, the cap now has headroom that it did
  not have in May — but the positive source still does not exist.
- **Reserved, unwired:** `percept`, `resonance`, `tool_error`, `manual`.

So roughly three of eight variables can move, and the one that expresses adversarial
edge cannot move at all.

### 3. Findings — where it hurts

Ordered by how much they cost right now, not by how interesting they are.

**F1 — A signal is destroyed on every tick, irreversibly. (bleeding)**
`satan-sensor-content` enqueues `reason: "content_backlog"` (`satan-sensor-content.el:122`);
the daemon's sensor reason set has no `ContentBacklog`, so `parse_inbox_payload` fails
and `process_outcome_row` **deletes the row** and logs one error line
(`run_loop.rs:527-548`). The broker then advances the content probe watermark
(`satan-sensor-content-probe-commit`), so the evidence is consumed and gone. ISS-011
records 22 rejections in 3 days as of 2026-09-14, i.e. ~7/day since at least 2026-09-11;
nothing in either repo's history suggests it was fixed. **[verify]**

RFC-016's Phase 0 recorded the same rows as a *poison message* blocking startup. The
current code deletes them on parse failure, which traded a stuck queue for invisible
data loss. Both states are wrong in opposite directions; the correct one is in F2.

**F2 — Forward compatibility is a human convention, not a contract.**
Only the payload *major* version is checked (`rpc::check_schema_major`). An additive
reason is indistinguishable from garbage, so an older daemon drops a newer broker's
signal. Three reasons have been added since September (`ask_suppressed`,
`ask_uncorrelated`, `reading`), and each time the rollout rule was prose: "attrd must
be redeployed before the broker emits it" (`design-contract.md` §16, 2026-09-24;
`wiring-status.md`, 2026-10-26). One deploy done out of order is a silent,
unrecoverable loss — F1 is exactly that failure, with timestamp.

**F3 — A transient database error permanently claims an outcome.**
`process_outcome_row` sets `claimed_at = NOW()` first, then does `read_projection` and
the dispatch. Any error after the claim leaves the row claimed forever; `drain` only
selects `claimed_at IS NULL` (`run_loop.rs:456-470`). There is no retry, no expiry, no
dead-letter table. Parse/schema failures are deleted (F1); everything else can silently
vanish mid-flight.

**F4 — Three switches, two truths.**
`attribute-updates-enabled` is (a) a broker defcustom forwarded in every outcome
payload, and (b) mirrored by a variable-watcher into `satan_attribute_settings`, which
(c) the daemon's decay scheduler reads at tick start. Plus
`satan-attribute-listener-enabled` for the transport. The watcher only fires on `set`,
and the capsule hides values based on the *defcustom*, while decay obeys the *row*. A
`setq-default`, a non-`set` mutation, or a settings write that fails silently (it is
swallowed: `satan-attribute--on-enabled-change`) splits the two truths with no alarm.

**F5 — Two migration lineages on one database. (RSK-015, open)**
Broker migrations are `0001..0009` tracked in `schema_migrations` (elisp runner); daemon
migrations are `0007..0012` tracked by `sqlx::migrate!` in its own table. Two different
`0007`s now name two different things in one database (`patterns` vs `attributes`). The
runners do not collide today; an operator reading the DB cannot tell which lineage a
number belongs to, and the next person to add `0010`-something picks a side by accident.

**F6 — The docs are in the wrong repo and some are lies.**
The normative contract (`design-contract.md`, 940 lines) and every theme doc live in the
broker repo; the code lives in the daemon. The daemon's own entry points are stale:
`README.md` says "**Scaffold only**" and points at `~/.emacs.d/docs/satan/…`, a path
that has not existed since the extraction; `HANDOVER.md` (2026-05-23) still describes
T-attr-1c as the next step, five months of work ago; `.doctrine/` there contains stock
memory only — no backlog, no slices — and the real history sits in `.spec-driver/`,
which doctrine marks deprecated. Meanwhile the *broker's* `wiring-status.md` asserts
"No decay implemented (§8)" and "Shame accumulates monotonically" while decay has been
shipping since 2026-05-29. Every attempt to approach this side starts by being
misinformed.

**F7 — Nothing can explain a value.**
`satan_attribute_events` is the append-only truth, and the only reader is `rebuild`.
Neither the model nor the operator can ask "why is Doubt 0.62" and get
`(reason, delta, ts, evidence)` back. The capsule shows eight bars and eight numbers
(`satan-attribute-render.el`), which is a display of a state whose derivation is
invisible. This is the main reason the layer *feels* opaque to work on: there is no way
to read it back except by SQL.

**F8 — The only consumer is prose.**
Attributes enter the capsule and bias nothing. No gate reads them, no mode is chosen by
them, no budget is shaped by them. The intended consequences live in unfrozen/undone
work: IMP-012 (arrival gate: attributes as a stochastic scheduling surface, 2026-05-30)
and the frozen-corpus ADR-002 (metabolic arrival gating, "proposed, blocked" per
RFC-016). Until one of those is accepted, the layer is a very well-tested display of
eight numbers — and the honest question is whether that earns its architecture
(POL-001's earns-the-seat test).

### 4. Opportunity — what would make this side fulfilling

- **O1 — Make loss impossible, not just unlikely.** One rule with three parts: unknown
  `(source, reason)` pairs are *stored opaquely*, never deleted; failed dispatches go to
  a dead-letter with the error; claim expiry so a crash cannot orphan a row. Small, and
  it converts every future vocabulary skew from data loss into a visible backlog.
- **O2 — Give the loop a vocabulary handshake.** A daemon-advertised capability set (or
  a `satan_attribute_settings` row carrying the accepted reason set) that the broker
  consults before emitting, so "redeploy attrd first" stops being folklore. Cheap once
  O1 makes the failure visible.
- **O3 — Build the "why" reader.** One query per attribute returning the last N events
  with `(ts, source, reason, delta, old→new, evidence)`; expose it in the capsule as a
  single provenance line per attribute ("Doubt 0.62 ↑0.15 contradicted 11:04") and as an
  operator command. This is the change that makes the layer approachable — it is the
  difference between a bar chart and a system you can interrogate. It also gives the
  model something to reason *with* rather than merely *around*.
- **O4 — Collapse the switches to one truth.** The settings row is the authority; the
  defcustom is its UI; the capsule renders from the same row (it already reads the
  projection directly). Delete or hard-reject the divergent paths. Include the listener
  switch in the same story.
- **O5 — Decide what attributes do.** Two defensible answers, and they lead to opposite
  architectures:
  - *Consumer*: accept an arrival/gating surface (IMP-012's shape, ADR-002's intent) so
    metabolism decides when and how SATAN arrives. This is the fulfilling version, and
    it is the one RFC-016's diagnosis argues for — being ignored should cost something.
  - *Telemetry*: declare the layer an observability surface, drop the daemon-shaped
    ambitions (or fold it into the observer per IMP-009's family), and stop tuning
    deltas nobody acts on.
  Everything else on this list is worth doing under either answer; the delta-tuning and
  reserved-source work is only worth doing under the first.
- **O6 — Unlock the locked.** `resonance` → Suspicion is the canonical trigger and the
  cheapest unlock (the percept already computes cue handles every tick). `tool_error` →
  Metamorphosis/Doubt is next. Cruelty needs a positive source *and* relies on O5 to
  matter at all.
- **O7 — Consolidate the governance.** Move the normative contract to where the code is,
  or move the code's docs' authority clearly; refresh `README`/`HANDOVER`/
  `wiring-status`; give `satan-attrd` a doctrine backlog so its work is visible in
  `doctrine status` rather than in a deprecated `.spec-driver` tree. Retire the
  `.spec-driver` residue honestly (archive, not silence).

### 5. Priorities I would defend

1. **F1 today, whoever owns the vocabulary.** Either add `ContentBacklog` to the
   daemon (which needs a §6S delta row — a contract amend, so: curiosity, and probably
   `+tiny` with the same partial-satisfaction reading as `segment_backlog`) or stop the
   broker emitting it. The two-line fix is not the point; choosing *which side owns the
   reason vocabulary* is.
2. **O1 + O2 within a week.** Loss becomes visible, then negotiated. This removes the
   class of failure that F1 is an instance of, and it is the cheapest possible insurance
   for a two-repo system with independent deploy cadences.
3. **O3 next.** The reader is what turns this side from archaeology into a system. It is
   also the prerequisite for any sensible delta tuning: you cannot tune what you cannot
   see. It gives the model provenance, which is a behavioural change in itself.
4. **O7 cheaply and early.** Every future session on this side pays the stale-docs tax.
   One pass: three stale docs, one moved contract (or a pointer in both directions), one
   backlog in the daemon repo, findings from this RFC filed as items.
5. **O5 as a decision, not a build.** Write it down — consumer or telemetry — before
   spending another hour on delta magnitudes or reserved sources. Everything in O6 is
   premature until then.
6. **O6 after O5 = consumer.** In order: `resonance` (Suspicion), `tool_error`
   (Metamorphosis), Cruelty as a cascade (needs cross-attribute reads during dispatch,
   which the dispatcher does not do today — §6.3's snapshot is read-only and pre-dispatch).
7. **F5 (RSK-015) as household maintenance.** Not urgent, cheap to regret: prefix the
   daemon's migrations (`attrd_0001_…`) or move them to a dedicated schema before the
   next one lands.

### 6. Breadcrumbs

**First hour, on a host with the database and systemd** (this is the set of checks that
would settle every **[verify]** above in about ten minutes):

```bash
systemctl --user status satan-attrd
journalctl --user -u satan-attrd -n 500 | rg -i 'parse failed|unknown|schema_version|ERROR'
psql -d satan_memory -c "SELECT count(*), count(claimed_at) FROM satan_outcome_inbox"
psql -d satan_memory -c "SELECT name, value, last_decay_at FROM satan_attributes WHERE scope='global' ORDER BY name"
psql -d satan_memory -c "SELECT source, reason, count(*), max(ts) FROM satan_attribute_events GROUP BY 1,2 ORDER BY 3 DESC"
psql -d satan_memory -c "SELECT count(*) FROM satan_audit_replies"
```

The third query answers "is the metabolism alive or sitting at the decay floor" (RFC-016
saw a flat 4–6 events/day of pure decay); the fourth names which sources actually fire;
the second catches F1/F2 in the act.

### 7. Open questions

- **Q1 — Does the attribute layer earn a daemon?** 4.5k lines of Rust, 107 tests and a
  systemd unit currently produce eight numbers that one capsule reads. POL-001's test
  ("does it use the editor as an editor?") justified *extracting* it; nothing yet
  justifies its *size*. Worth asking before adding a consumer, not after.
- **Q2 — Consumer or telemetry (O5)?** And if consumer: does arrival gating live in the
  broker (a timer that reads attributes), the daemon (a scheduler that emits an
  `arrival` source), or the harness?
- **Q3 — Where does the normative contract live** when the code and the contract are in
  different repos, and which repo's gate guards the pair? Today neither `just check`
  sees both.
- **Q4 — Opaque storage of unknown reasons (O1)**: does the projection need a
  zero-delta event row with `reason` as free text, or a separate quarantine table? The
  contract's §5 event schema is closed; this needs an amend either way.
- **Q5 — Is Cruelty salvageable?** With decay live, is doubt + shame ever low enough for
  headroom in practice, given Shame rises +0.30 on `harmful` and falls −0.025 on
  `worked`? If not, the attribute is decorative and should be retired rather than wired.
- **Q6 — Should the capsule show provenance (O3) or stay a bar?** The render contract is
  explicit about shape; a provenance line is a contract change and possibly a real
  behaviour change (the model may reason differently about a value it can trace).

### Non-goals

Not in scope for this RFC: new attributes; per-pattern or per-hypothesis scopes (closed
by contract §3); model-writable attribute values (invariant 7); re-deriving the brief's
semantics; rescuing the epistemics roadmap through the attribute layer (that is the
pattern layer's job, and it has its own problem — see ISS-063).

## Outcome

Open. Proposed dispositions, in order of cost:

1. F1 fixed and the vocabulary-ownership question answered (broker-owns vs
   daemon-owns).
2. O1 + O2 accepted as one small improvement: no silent loss, negotiated vocabulary.
3. O3 accepted as an improvement: the "why" reader, capsule provenance line.
4. O7 accepted as chores: three doc refreshes, a backlog in `satan-attrd`, contract home
   decided.
5. O5 decided — **consumer or telemetry** — before any reserved-source work is scoped.
6. O6 (resonance → Suspicion) scoped only if O5 says consumer.

Unresolved and needing the operator: Q1 (does the daemon earn its seat), Q2 (where
arrival gating would live), Q3 (contract home), Q5 (Cruelty).
