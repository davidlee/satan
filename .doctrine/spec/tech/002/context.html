SATAN as it runs today

One Emacs daemon hosts the broker and every authority item. Peers couple to it through two buses: Postgres tables with NOTIFY, and plain files.

Reading it

  • The broker is the only component that enacts actions; jailed agents propose over JSONL or MCP.
  • Postgres doubles as an RPC bus: satan_outcome_inbox, satan_audit_inbox, patch_jobs + pg_notify. The broker LISTENs via satan-attrd notify-stream.
  • Files: panopticon writes behaviour/; goad reads state/goad/queue.json and writes ~/satan/goad/data/; the model-facing corpus is ~/satan.

Known gaps (SPEC-002 NF-003, NF-004)

  • Jails that serve MCP also bind the Emacs server socket: arbitrary elisp, bypassing the protocol.
  • The harness inherits the Emacs cwd (~), and the jail binds $PWD read-write (probable; verify).
  • The tick timer fires once per boot; the patcher has never completed a job.
