## Synthesis

SL-027 delivers what it set out to: the interactive malebolge daemon runs
under a room profile — its coding tools execute in room `assistant` as user
`satan`, its model calls leave only through the gateway socket, and the host
jail grants nothing beyond the §4.7 inventory. The evidence is live, not
textual: the first live start of the jailed daemon (PHASE-06) ran `bash` in
the room as satan; probes inside the daemon's own namespaces showed
ENETUNREACH on v4/v6 with the gateway forwarder the one route, every absence
§6 lists, and EROFS on the door root; two patch jobs submitted by the jailed
agent itself showed satan can clone `/work` and never write it, during and
after a job, with a concurrent session; the human run (VH-1) confirmed cwd,
room-side writes, an unchanged ~/notes, MCP reachability and the
`room unavailable` fault with the session continuing.

The closure gate (EX-4) holds: all 37 tools of the live interactive set were
classified against criteria fixed before the sweep; none can carry data off
the host. The one judgement call — `speak` to a default sink that could be an
AirPlay device — was ruled not blocking by the user (switching sinks is a
human act). The audit set is egress-free by care, not enforcement (§7
accepted residual, RSK-019).

Gates green: satan 1305/1309 (4 skips), malebolge 1600/1600 (98.2% stmt),
`check-jails` incl. `malebolge-jail-profile`. VT criteria all present
(UNATTRIBUTABLE is the cross-repo attribution limit).

What remains is truth-telling, not code: the design text lags the delivered
API, launcher and room facts in four clusters (F-1..F-4), and the drafted
governance revisions (§4.9) are due. One stale comment was fixed (F-5); a
pre-existing argv defect found by the sweep is owned by ISS-051 (F-6).

Standing risks: room-action audit gap (T3 → ISS-050, pre-existing);
egress-free MCP set by convention only (RSK-019); clone needs `--no-local`
(documented to the agent in room.txt).
